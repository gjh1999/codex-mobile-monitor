# Codex / Claude Code 双客户端

[文档索引](README.md) · [运行与维护](RUNBOOK.md)

Qt 桌面工作台提供 **Codex** / **Claude Code** 切换。两个后台分别工作；切换只改变当前展示，不关闭另一端，并保留各自的任务选择和输入草稿。Tk / Win32 回退界面不提供完整双客户端功能。

## 接入与操作

1. 选择客户端和任务。同一个本机 Codex 会话可在桌面和 VS Code 终端接续。Claude 后台从 `CLAUDE_CONFIG_DIR` 或 `~/.claude` 读取本机会话和对话。历史扫描不发起模型请求。
2. 点击“接入任务”。原窗口仍占用会话时只读关注；先在原客户端退出该会话，再重新接入才能控制。
3. 接入后可修改本机显示名称、发送消息、暂停、继续或移出。重命名只保存到本监控本地，不改写 CLI 转录。
4. Claude 运行中的消息通过 CLI stream-json 的 `priority: now` 输入插队到当前会话，不启动第二个 CLI。暂停走单独的带队列取消标记的 interrupt，防止刚插入的消息在暂停后又启动。
5. 工具需要确认时，在审批窗口核对实际操作。可以同意勾选项、同意全部可核对项或拒绝当前请求。 [桌面审批操作](DESKTOP.md#审批窗口)
6. 界面上的操作已提交表示后台接收请求；查看最终结果。失败会弹窗，消息发送失败且输入框为空时恢复原草稿，已有新草稿不会被覆盖。送达结果不确定时不自动重发。
7. “移出”不删除原任务，也不停止它已开始的工作；暂停则会阻止本监控继续发送后续指令。

“创建测试任务”只创建本地草稿或会话，不自动启动一轮模型。

## 支持范围

| 能力 | Codex | Claude Code |
|---|---|---|
| 本机任务与对话发现 | app-server 列表及本机历史标签，桌面只读合并原生 JSONL 与本连接消息 | 本机 JSONL 增量读取并合并本连接消息 |
| 外部窗口占用 | 尊重写入锁，进入观察模式 | 通过 live 元数据检查外部会话，保持只读 |
| 接入后发送 | 空闲时 `turn/start`；执行中用 `expectedTurnId` 补充指令 | 在本监控拥有的 CLI 输入流插入 `priority: now` 消息；运行中的 turn 由 CLI 处理插队 |
| 暂停 / 继续 | 需要控制权；原任务已运行时，“继续”只解除本地暂停并恢复消息发送，不启动或插入额外轮次。额度可手动重试，完成/预算限制保留 | 暂停使用同一会话 interrupt 并取消等待消息；继续要等暂停确认且当前轮次结束 |
| 自动推进 | 经过所有权、实时状态、goal、审批和持久预留检查；额度耗尽后等待刷新并重新确认恢复 | 本监控本地定时器；默认关闭，手动开启后一小时检查，仅空闲、可控制、无审批或执行错误时发送 |
| 工具审批 | 本连接收到的具体请求，可配置精确命令规则 | 本 CLI 子进程收到的单次工具申请，无自动审批规则 |
| 官方额度 | 显示实际额度、刷新时间及等待状态；只有服务端明确允许，才恢复原来的额度受限目标 | 本实现没有相应接口，显示未知 |

Codex 界面接入默认开启“自动推进”，“关闭自动推进”保留接入和手动控制。开关本身不授予所有权，也不创建目标；已授权原目标因额度进入 `usageLimited` 时，独立恢复流程可在刷新后、服务端明确确认可用时仅将其状态恢复为 active。手动暂停、关闭开关和移出均取消自动恢复；目标内容、用量和预算保持不变。Claude 不进入 Codex 调度器。

Claude 沿用 CLI 的工作目录、登录和本机模型配置；默认自动发现 CLI，也可设置 `CLAUDE_CODE_PATH`。项目使用 CLI stream-json 控制适配，不依赖额外的模型 Python SDK。

## Codex 桌面与 VS Code 终端续接

两端使用同一个 Windows 用户和 Codex 数据目录时，在澜汐「案头诸事」选择终端正在使用的会话，即可在「灯下对谈」读取该会话已落盘的用户消息与可见回复。Codex 数据目录默认是 `~/.codex`，两端也可使用同一个 `CODEX_HOME`。不同数据目录各自保留会话。

澜汐接入后写入的轮次仍属于同一个 Codex 会话。终端退出前可在澜汐查看已落盘消息。需要发送消息时，从对方释放写入权，再在当前一端接续该会话。只读合并不会改写原生历史，也不会因读取旧消息补发通知。

桌面按现有窗口显示最近最多 50 条可见消息。冷读检查未压缩 `.jsonl` 的末尾最多 16 MiB，此后增量读取新内容。工具调用、内部上下文和未写完整的行不会进入对谈。手机 Web 沿用此前已记录的本机消息范围。跨设备续接按原有签名交接流程处理。 [跨设备会话交接](HANDOFF.md)

## 状态与数据隔离

Codex 和 Claude 的任务、控制操作、回复和草稿分别保存；同名任务或相同操作编号不会跨客户端执行。界面从内部后台模块获取当前客户端的快照，审批按客户端筛选。状态文件及根目录规则见 [配置说明](CONFIGURATION.md)。

桌面操作包括创建测试任务、接入、移出、开启或关闭自动推进、暂停、继续、发送消息和重命名；客户端不支持的操作会被拒绝。任务别名是 1–80 字单行文本，保存在各客户端控制库的 `task_names` 表。每项操作带有请求编号，重复编号不重复执行，不能用同一编号提交不同内容。

## 验证范围

Python 回归测试覆盖协议适配、观察/控制边界、操作去重、审批、增量会话读取和后台客户端路由。Qt smoke 使用虚构会话、替代后台与临时数据，点击生产界面的切换、发送、暂停和重命名等按钮并检查状态。运行命令统一见 [运行与维护](RUNBOOK.md)。

这些检查不代替真实模型发消息、工具审批往返或钉钉联网验收。过去的测试数量和现场结论保留在 [历史文档](archive/README.md)，仅适用于记录当时的范围。
