## 2026-11-20 个人版与云服务审查

以下是 R21 到 R23 阶段的审查结果。

| 优先级 | 发现及影响 | 验收条件 |
| --- | --- | --- |
| 已修正 | 初版 R21 的后台自动克隆目录与首启选择分开。修正版发现母目录中已有 GitHub origin 的项目，发布项目相对路径，在另一设备的母目录内按原有层级克隆。既有工作区优先复用。 | 回归覆盖不同母目录、多层中文项目名及在原目录编辑后的回传；两台物理电脑的休眠重连仍待验收。 [项目发现](../project_library.py) · [同步绑定](../personal_sync.py) |
| 现场验收 | R23 可通过 HTTPS 配对码连接私人协调服务，首启同屏设置项目母目录与配对码。托盘显示连接和重试状态。 | 两台物理机登录、休眠唤醒、断网重连后自动恢复，以真实 GitHub 提交及同一 Codex 会话续写计时。 [云端配对](CLOUD_COORDINATOR.md) |
| 中 | 服务端一次返回个人空间的全部记录索引，包含删除标记。客户端读取索引时也套用单条记录的 10 MiB 响应上限。由代码可知索引超过该值时，已缓存项目可以继续尝试同步 Git，记忆通道会报告不可用。线上空间尚未测到此上限。 | 索引分页或增量读取，并覆盖分页期间有其他设备写入的情况。 [记录协议](../personal_relay.py) · [降级逻辑](../personal_sync.py) |
| 中 | 阿里云容器与本地六个关键模块的 SHA-256 一致，只在服务器回环地址监听。健康接口仅报告进程就绪。本次用两份设备配置在同一台 Windows 上完成云端写入和回执。当前私人配置启用个人同步，计算调度及项目控制权另需配置。 | 对生产数据做独立备份与恢复演练，在两台物理电脑分别核验项目、长期记忆及会话。 [协调服务](../coordination_server.py) · [部署说明](CLOUD_COORDINATOR.md) |
