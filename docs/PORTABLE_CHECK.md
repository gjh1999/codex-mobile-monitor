# 澜汐 R28 安装、升级与验收

## 在另一台 Windows 电脑使用

收到私人下载脚本时，将单个 `下载澜汐-R24.cmd` 放在笔记本的可写文件夹中并双击。它用 Windows OpenSSH 客户端下载对应 ZIP 到同一文件夹并校验 SHA-256。脚本内的限时凭据仅供读取这份安装包，请私下传送。解压后运行桌面程序。

1. 将便携包解压到目标电脑本地可写目录。
2. 双击便携目录里的 `Lanxi-Glass-R28-Portable.exe` 启动。代码同步需要 Git for Windows，终端接续需要本机安装并登录 Codex CLI。
3. 在首次启动窗口粘贴另一台电脑生成的一次性配对码，选择本机的项目母目录，再点「连接并同步」。已经用过澜汐的电脑可从托盘选择「跨机接续 → 使用配对码连接」。已配对的电脑选择「邀请另一台电脑」生成新码。 [云端配对说明](CLOUD_COORDINATOR.md#在澜汐中配对)

## 升级与首次配置

### 在已经用澜汐的电脑升级

首次升到 R24 时，通过系统托盘退出旧澜汐，再打开新版。若旧版使用固定用户数据目录，新版会立即读取原有配置。早期版本的数据放在旧 EXE 同目录时，可用旧版目录迁移。旧目录保留作备份。

从 R24 起，HTTPS 配对成功后澜汐会定期检查更新。收到提示后点确认，后台会下载并校验 ZIP，将新版写入用户目录下的独立版本文件夹，然后退出并打开新版。当前有对话或审批时先保存新版，结束后可从托盘「检查更新」切换。

从托盘「跨机接续 → 查看大文件清单」显示本机缺少或大小不同的文件、项目内相对路径、大小及上次清点到文件的设备。Git 已跟踪且本机已有的 100 MiB 及以上文件自动登记，Git 忽略的文件可以手动登记。

偶尔需要修改另一台电脑上的大文件时，在笔记本从「跨机接续 → 借用另一台电脑的大文件」选择来源及文件。两台电脑的澜汐需保持运行。等状态显示可编辑后，在本机项目的原相对路径打开文件。保存后用「查看大文件借用与回传」选择该文件回传。

来源电脑验证原版文件后应用修改，并保留本机恢复副本。如果来源文件有新改动，记录显示冲突，两端继续保留自己的一份。两种结果都只在双方完成交接后清理服务器临时文件。服务器至少预留 5 GiB，空间不足时传输会显示原因。

迁移完成后，配置、配对、项目索引、对话记录、随记、待办和本机草稿保存在 `%LOCALAPPDATA%\Lanxi\data`。托盘的「打开用户数据目录」可查看。今后换安装目录也会读回这份数据。项目文件、Codex 原生记忆和会话按原位置使用。

### 选择项目母目录

两台电脑可以选不同盘符。来源机在母目录下的 `客户甲\工具组\项目 A`，在新设备上也会克隆到所选母目录的 `客户甲\工具组\项目 A`。直接在这里打开、修改代码。项目记忆目录随项目一起对齐。

首次使用时，选存放各个项目的上一级文件夹，例如 `D:\Projects`。澜汐识别 Git 仓库和带常用项目文件的目录，会在 Codex 案头加入可启卷的项目条目，并归拢有对应本机路径的 Codex 会话。选择项目条目可查看分支、记忆位置和发现的记忆文件。项目目录里新建或克隆项目后，后台每约五秒更新一次。托盘的「设置项目母目录」可随时重设。

## 运行验收

R25 中从托盘选择「测试」。澜汐会在窗口中显示本机自检和云配对检查的进度。双机通信可在一台点「发起双机测试」复制测试码，在另一台粘贴后点「回传测试」。窗口显示报告的保存位置。

同一个 GitHub 项目要在两台电脑上验收控制权时，请都使用 R24。先在第一台接入任务，第二台应显示项目被占用；第一台完成轮次后点击「交还任务」，等同步完再从第二台接入。IDE 上报插件需另外安装一次。 [跨设备项目控制](PROJECT_CONTROL.md#个人版项目占用)

双击 `验收.cmd`。选项 1 用独立的测试副本、临时代码仓库与会话验证同步，需要 Git for Windows。选项 2 和 3 读取本机已有的云配对，用真实服务交换一次性测试记录。三个选项均可直接运行，无需单独安装 Python。

### 本机自检

直接回车选 **1**。依次模拟源电脑和接收电脑，检查空工作区自动克隆、代码与项目记忆双向更新、全局 `AGENTS.md`、已完成的会话记录，以及 检查不足 100 MiB 的文件已检出，达到 100 MiB 的文件留在源端。

### 阿里云双机通道验收

先在两台电脑完成设备配对。从托盘「跨机接续」核对「已连接协调服务」。验收程序读取当前 Windows 用户的配对配置和凭据。使用早期手工 SSH 配对的设备时，先启动各自的 SSH 隧道。 [配对与连接](CLOUD_COORDINATOR.md)

源电脑双击 `验收.cmd` 选 **2**，保持窗口打开。接收电脑选 **3**，输入源端生成的测试码。源端在二十分钟内收到另一设备名的回执即通过。测试只交换一次性记录，结束时清除记录内容。这个模式验证真实协调服务、隧道和设备配对。代码克隆和文件过滤用选项 **1** 测试，真实 GitHub 项目与原生会话续写按下文及云协调服务文档现场验收。

各模式都生成 JSON 报告，位置显示在窗口末尾，通常在 `%LOCALAPPDATA%\Lanxi\验收报告`。失败时查看报告中最后一个通过的步骤和错误。

## 终端和澜汐接着同一段对话

从终端切到澜汐时，等当前一轮结束并退出 Codex，再到「案头诸事」点开原会话，接入后就能在「灯下对谈」继续发消息。原终端还占用会话时，澜汐显示已保存的对话并等候写权限。

从澜汐切回终端时，在「案头诸事」右键点原来的 Codex 会话，选「查看会话 ID」，在弹窗点击「复制 ID」。解除澜汐对该会话的接入，再用同一 ID 在终端恢复。也可在 Codex 终端里用 `/status` 查看 ID。

新终端进入同一项目后，`codex resume` 会打开会话选择器。只想继续当前目录最近一次会话，用 `codex resume --last`。同一项目有多个任务时，直接指定会话 ID。

```powershell
codex resume -C "E:\Projects\A" "原会话的 UUID"
```

换电脑时，等澜汐同步项目和已完成的会话记录，再用该电脑的项目路径和同一个 ID 运行上面的命令。验收脚本检查会话记录到达，真实对话续写可用上面的命令亲自确认。 [Codex CLI 命令参考](https://learn.chatgpt.com/docs/developer-commands?surface=cli#codex-resume)
