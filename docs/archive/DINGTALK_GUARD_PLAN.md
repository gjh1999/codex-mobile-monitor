## 1. 目标与决策

在电脑上运行一个独立守护程序，以钉钉作为 iPhone 的消息入口。用户离开电脑后，可以收到任务进展、异常、额度变化和待审批提醒；对工具托管的 Codex 会话，可以查询状态、暂停自动续跑、继续任务，以及人工决定具体审批请求。

核心由三部分构成：**钉钉消息通道、长程任务调度器、Codex 会话与审批桥接器**。网页只用于辅助查看，不作为手机接收提醒的前提。不使用桌面、浏览器、鼠标或键盘模拟；不修改 Codex 全局权限来代替审批。

默认决定：每 10 分钟检查任务；只自动推进明确登记并启用的长程任务；优先实现钉钉通知和调度验证，再开放可信双向操作。当前已有研究线程的自动续跑由原宿主管理，在可靠接管前禁止另一个守护器再次唤醒它。

## 2. 用户实际使用流程

### 2.1 收到消息

电脑检测到训练完成、任务停滞或待审批 → 生成脱敏事件 → 通过钉钉机器人发送 → iPhone 钉钉收到通知。正常情况下不发送每一条日志；仅推阶段变化和定期摘要。

### 2.2 查询与控制

双向机器人接通后，可支持以下结构化指令：

| 指令 | 行为 | 不应产生的副作用 |
|---|---|---|
| 状态 | 返回登记任务、最近活动和运行状态 | 不续跑任务 |
| 额度 | 返回真实额度窗口、更新时间和重置时间 | 不购买额度、不重置额度 |
| 继续 任务编号 | 为允许控制的空闲任务安排一轮工作 | 不重复启动活跃任务 |
| 暂停守护 任务编号 | 暂停该任务的后续自动唤醒 | 不擅自杀死 GPU 训练进程 |
| 恢复守护 任务编号 | 恢复定时检查 | 不更改研究范围 |
| 待审批 | 列出当前仍有效的请求摘要 | 不默认批准 |
| 允许 请求编号 | 对已展示详情的特定有效请求批准一次 | 不生成永久允许规则 |
| 拒绝 请求编号 | 拒绝该请求 | 不影响其他请求 |

自由文本不能直接转成系统命令。复杂新任务应先形成明确任务描述，再进入 Codex 的正常执行和权限流程。

## 3. 钉钉接入路线

### 3.1 第一阶段：单向通知适配器

若用户当前钉钉群允许新建自定义机器人，则采用其签名 Webhook。电脑只需发出 HTTPS 请求；用户创建机器人后，在本地填写 Webhook 与签名密钥，不在聊天、日志或 Git 中公开。

这个渠道只能完成通知，**不能仅凭 Webhook 实现接收用户回复和审批回传**。当前租户的机器人可创建性、平台策略和实际返回码需要验证；不能因为旧教程有入口就保证当前账号可用。若不允许创建，跳过旧式 Webhook，直接使用下述应用机器人。

### 3.2 最终路线：应用机器人 + Stream

使用钉钉官方 Stream SDK 接收机器人消息、事件或卡片回调，电脑维持出站连接。需要用户账号具备创建/配置应用及机器人能力，准备 Client ID、Client Secret 和允许操作的发送者/会话标识。

优先采用“文本指令 + 明确请求编号”完成双向闭环。交互卡片作为增强；卡片模板、权限和回调仍需当前租户实测，不预先承诺任何卡片都能直接使用。

官方 SDK 确认支持上述接入类别：[DingTalk Stream Python SDK](https://github.com/open-dingtalk/dingtalk-stream-sdk-python)。其提供消息回调和回复示例。具体应用权限、上线/发布要求以用户后台实际回执为准，不凭接口调用成功推断组织内已生效。

### 3.3 外网使用

钉钉通知及 Stream 指令无需手机与电脑处于同一 Wi-Fi。辅助审批网页若仅在局域网提供，则手机离开该网络不可访问；不将现有 HTTP 监控端口直接作为公网远程审批入口。

第一版可保留本机查看页面；真正的手机审批优先通过已认证身份的钉钉 Stream 指令。若以后引入跨网网页，需另行完成受控访问与 HTTPS 部署验收。

## 5. 系统结构

```text
Codex app-server / 托管任务
        │ 实时状态、待审批、额度
        ▼
会话连接器 ──────→ 状态与审批存储
        │                │
        ▼                ▼
定时任务检查器       钉钉事件通知
        │                │
        │                ▼
        │           iPhone 钉钉
        │                │ 白名单身份 + 明确指令
        ◀────── 操作路由与审批校验
```

建议模块：`codex_rpc.py`、`task_store.py`、`scheduler.py`、`approvals.py`、`notifications/dingtalk.py`、`dingtalk_stream.py`、`status.py` 和本地辅助页面。可分步从当前 `monitor.py`、`automation.py` 提取，避免同时启动两套后台调度。

## 6. 真正的定时守护行为

每轮检查以下条件，只有全部满足才发送一次续跑：

1. 任务在用户明确启用的登记表中，且为未完成长程任务。
2. 本守护器拥有该会话的可靠执行连接与独占调度权。
3. Codex 实时状态明确空闲，没有待处理审批或需要用户输入。
4. 不存在本守护器正在执行的续跑请求；冷却时间已结束。
5. 没有额度阻塞或需要退避的连续错误。
6. 发送前再次验证状态，并先持久记录本轮请求身份。

`notLoaded`、查询超时、连接丢失、未知状态均不是“空闲”。不得仅凭日志暂时不更新或文件锁不存在就启动第二个执行器。

任务登记至少包含：任务 ID、会话 ID、工作目录、目标/计划书路径、启用状态、检查间隔、所有权、当前轮次、下次检查时间、最近错误与退避次数。目录从登记信息读取，不执行钉钉消息中任意传入的路径。

每次唤醒提示要求 Codex 读取当前计划、进度与外部进程状态，再选择一项真实可推进工作；没有可推进工作时记录阻塞条件，不为了活跃制造无意义改动。完成、暂停或明确等待用户的任务不持续刷消息。

## 7. 去重、恢复与错误处理

- 续跑采用单实例进程锁、任务锁和持久请求记录，处理“已发送但响应丢失”的不确定状态。
- 对不确定的发送结果先核验真实运行状态，不能立即重发。
- 失败后建议 1、2、5、10、30 分钟退避，设置上限；恢复成功后清零。
- 守护进程重启不会自动接管其他客户端活跃会话，不重放历史审批或已发送续跑。
- 电脑休眠/关机期间不能执行检查；重新运行后恢复登记任务。钉钉消息不能据此自动开机。
- 初版使用可观察的用户级进程；开机启动在核心验证后配置，不使用隐藏桌面操作。

## 8. 手机审批的协议边界

Codex 官方 app-server 支持命令、文件变更和权限请求。请求必须保留原连接、JSON-RPC request ID、thread/turn/item ID 与完整请求内容。[官方审批协议](https://learn.chatgpt.com/docs/app-server)

流程：接收真实请求 → 持久记录并生成短期展示编号 → 钉钉通知 → 核验发送者身份和对应会话 → 展示具体请求 → 用户选择一次允许/拒绝 → 在原连接回应 → 等待服务端确认已解决 → 通知结果。

至少展示：任务名称、具体命令或文件变更摘要、目录、请求原因、网络目标/文件权限范围、有效期。完整命令不能被静默截断；若不便在群中展示，需经认证详情页或私有会话明确查看，不能对隐藏内容批准。

默认只支持本次允许和拒绝，不提供“永久允许所有操作”。文件写入范围必须遵守请求本身；未知请求类型不按普通命令批准。过期、已解决、断连、所属任务变化或重复点击均不执行第二次批准。

第一版只对本工具托管连接收到的请求有效。当前桌面对话中的审批在未完成可靠桥接前标为“不支持”，不通过点击桌面来假装接通。系统或平台明确禁止的操作也不能由该工具绕过。

## 9. 额度与训练状态

额度调用官方 `account/rateLimits/read`，记录返回的窗口、已用百分比、重置时间和采集时间；不同模型/窗口分开显示。接口未返回时为“未知”，旧数据保留时必须标“已过期”，不把累计 token 当剩余额度。

额度查询失败只影响额度模块，不能销毁承载运行任务和待审批的连接。认证失败、权限错误、限流和网络错误分别记录；不自动购买额度、不自动消耗重置权益。

训练状态读取本研究固定目录内的损失日志、检查点和已确认进程/会话句柄。最近日志时间不能单独证明进程仍活跃；状态应区分运行、完成、失败和未知。禁止发送 API 密钥、访问令牌、Webhook 地址或原始医学图像到钉钉。

## 10. 通知规则

| 事件 | 默认策略 |
|---|---|
| 等待人工审批 | 立即一次，快过期时最多一次提醒 |
| 训练/任务完成 | 每次完成发送一次 |
| 执行失败或长期无进展 | 立即或达到预定阈值发送，重复错误合并 |
| 额度接近阈值 | 可配置 20%/10% 剩余量，必须来自真实接口 |
| 定期进展 | 每 60 分钟摘要，可关闭 |
| 常规日志与每步 loss | 不逐条推送 |

Webhook 请求成功不等于手机确实弹出通知；需检查业务返回码，再由用户实际看到消息完成最终验收。推送失败保留待重试事件并退避，日志只记事件 ID 和脱敏错误。

## 11. 双向指令的身份和防重放

Stream 接入后仅接受本地白名单中的用户标识和群/会话标识。收到其他人的命令不操作 Codex。钉钉回调重试只产生一次业务动作。

审批采用请求 ID 与单次随机标识、有效期和决策状态；不把任何聊天文本“同意”匹配为批准全部。卡片或消息中的第三方内容不能成为执行指令来源。

通过公开群发送提醒时只发送必要摘要；机器人凭据和会话令牌保存到本地忽略文件或系统凭据存储，不写入代码仓库。辅助 HTTP 接口只接受授权 POST 产生变更，查看链接/预览不得触发允许操作。

## 13. 实施阶段与验收

| 阶段 | 工作 | 完成证据 |
|---|---|---|
| P0 现状审计 | 核对 CLI/schema、服务、配置和现有自动续跑 | 审计记录、测试清单；保留未知项 |
| P1 钉钉通知 | 签名适配、业务错误处理、去重、重试和脱敏 | 本地 HTTP mock 测试、配置模板；有凭据后真实回执 |
| P2 稳定连接 | 单个 RPC 连接生命周期、并发写入锁、退出清理 | 额度失败不打断审批，通知可持续处理 |
| P3 任务守护 | 持久登记、独占所有权、空闲核验、定时和退避 | 可控制 fake clock 与 RPC 的完整调度测试 |
| P4 审批闭环 | 原连接响应、过期/撤销/断连/重复处理 | mock 及工具托管测试任务的真实审批闭环 |
| P5 钉钉双向 | Stream、身份白名单、消息幂等、结构化指令 | 未授权者拒绝；用户能查询、暂停、恢复和审批 |
| P6 常驻与交付 | 单实例启动/停止、恢复、文档与移动端验证 | 电脑重启或服务重启后恢复；iPhone 实测 |

P1 可与 P2 开发并行；P3/P4 依赖可靠连接。未完成真实接入的阶段保持显式未完成，不用 mock 通过替代外部系统回执。

## 14. 必须覆盖的测试

1. 钉钉签名和 payload 格式；HTTP 成功但业务拒绝；限流与超时；错误日志不含凭据。
2. 同一事件重复通知、网络返回不确定、程序重启后的去重。
3. 活跃/未知/notLoaded/等待审批任务不被唤醒；空闲托管任务仅唤醒一次。
4. 同时触发定时检查、重启恢复和迟到响应不会产生两个执行者。
5. 未授权钉钉用户、错误会话、过期编号、已撤销请求和重复点击不能批准。
6. 额度接口失败不终止运行任务或审批连接；额度过期显示清晰。
7. 程序退出清理子进程，不留下重复 app-server；后台服务不靠桌面模拟操作。
8. 手机上的通知、状态查询和一次批准/一次拒绝均实际验证后才宣布交付。

## 15. 当前依赖与自主推进边界

现在可以自主完成：本地计划、代码、mock 测试、服务状态检查、调度演练、身份校验与审批机制测试。

真实钉钉发送和双向连接需要用户自己的机器人配置/应用凭据及指定收件会话。创建和发布应用所需组织权限由账号决定，不能由程序凭空生成。先把可审查代码、配置步骤和本地验收完成，再由用户在本机填写配置，不反复要求提供秘密到聊天。

## 16. 交付文件与完成定义

至少交付：本计划书、README、配置示例、本地秘密文件忽略规则、钉钉适配器、Codex 连接器、守护调度、审批处理、测试、启动/停止入口和实际验收记录。

真正完成意味着：用户 iPhone 钉钉收到真实消息，能查询真实或明确未知的额度；一个登记长程任务在空闲时被守护器按计划推进且不重复；一次具体权限请求能从手机允许或拒绝并回到正确会话。当前桌面对话若仍不可桥接，交付时必须明确适用范围，不能宣称控制所有 Codex 客户端。
