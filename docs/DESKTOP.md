# 桌面使用说明

[文档索引](README.md) · [启动、构建和维护命令](RUNBOOK.md)

## 窗口与后台

正式入口为根目录 `desktop_app.py`。源码运行优先选择 Qt，缺少 Qt 时回退到 Tk，再回退到 Win32；Qt 提供完整的 Codex / Claude Code 双客户端界面。Tk / Win32 是功能较少的兼容界面。

澜汐用原生 Qt 绘制整窗壁纸和两块同材质的毛玻璃。顶部居中的胶囊在 Codex 和 Claude Code 间切换。左侧「案头诸事」可以搜索和选择任务，右侧「灯下对谈」保留可滚动消息与固定输入区。托盘菜单可打开「运行与额度」。

顶部滑块可点击或拖动，按下时立即变亮，拖动时跟随指针，释放后以弹簧曲线停靠。再次切换时会从当前位置继续。系统关闭动画效果时立即切换。

点击左侧任务即可接入，接入成功后会断开同一客户端中的其他任务。接入失败时保留原有连接。断开会停止澜汐对旧任务的控制和自动推进，其已启动的轮次继续执行。

鼠标移入对谈标题区或键盘聚焦操作按钮，工具栏就会浮现。接入、暂停、继续依次叫「执舟」「暂泊」「续航」，自动推进用「扬帆」和「收帆」，移出和打开 VS Code 项目用「移离案头」和「启卷」。把鼠标停在按钮上可查看动作含义。双击对谈标题或聚焦后按 F2 就地改名，Enter 保存，Esc 取消。对话输入区用 Ctrl+Enter 发送。

待审批时弹出独立窗口，列出来源客户端、任务、本机执行设备、工作目录，以及命令或权限详情。可选择「拒绝」或「允许一次」。关掉窗口后仍可从对话区或托盘重新查看尚未过期的请求。

桌面程序自己启动后台工作线程。关闭开发终端或 Codex 窗口不会关闭已独立运行的 EXE；Qt 关闭窗口会缩到系统托盘，选择托盘菜单“退出程序”才会停止后台。0.7.3 修复“先隐藏到托盘、再退出”后 Qt 主循环残留的问题：退出显式结束主循环，后台停止、定时器和托盘清理仅执行一次，单实例锁保留到主循环结束后再释放。程序通过 Windows 单实例机制防止重复打开桌面实例。

`monitor.py` 是桌面进程内部的后台编排模块；应用统一从桌面入口启动。

## EXE 与数据

本轮毛玻璃版交付文件为 `release/Lanxi-Glass-R6.exe`。以已确认的 R4 界面为视觉基线，沿用 R5 的任务状态词，加入项目分组和「吉光片羽」。默认构建名为 `release/Lanxi.exe`。

同目录的桌面包使用相同配置和状态。上一版仍在运行时，先从托盘退出再打开新版。单文件内含 Python、Qt 和壁纸。运行任务需本机已安装并登录对应的 Codex / Claude CLI。

壁纸每 30 分钟离线轮换，默认依次为 Mavericks 海浪、Big Sur 白昼和 Catalina 夜景。系统关闭动画效果时，切换直接生效。可用 `desktopWallpaperMinutes` 调整间隔。中文标题和正文使用 Windows 本机字体。[macOS 原配壁纸档案](https://512pixels.net/projects/default-mac-wallpapers-in-5k/)

EXE 的 `local-config.json`、任务数据库、回复记录和草稿位于 EXE 同目录。源码运行则使用项目根目录，二者不会自动同步状态。`local-config.json` 是可选配置；数据清单见 [配置说明](CONFIGURATION.md)。

正式使用前应检查源码与 EXE 使用的数据根目录。构建预览版时可指定不同文件名。完整步骤见 [运行与维护](RUNBOOK.md)。

## 任务操作

案头按项目目录分组。同一个项目开多个终端时，各段会话显示在同一个可折叠组里。在 Git 项目的子目录启动终端也会归到仓库根目录。同名项目用父路径区分，搜索支持项目名、会话名和路径。

组内优先用本机已保存的会话标题。Codex 也可用本地记录中第一条有内容的用户消息作简短标题，手动更改的名称优先。左侧「待执舟」「执舟中」「已执舟」对应右侧「执舟」，「已暂泊 · 待续航」对应「暂泊」与「续航」。

手动设置的任务名称保存在每个客户端独立的本机 SQLite 控制库中。客户端切换会保留各自的任务选择和输入草稿，另一端后台继续监控。

重新接入保留已保存的手动暂停。如果 Codex 已在后台运行，但本地仍标记暂停，状态会明确显示“本地已暂停 · 后台运行中”，有控制权时“继续任务”保持可用。此时点击继续只解除本地暂停，恢复对当前轮次的消息发送，不补发继续提示词，也不新建轮次；原有自动推进开关保持不变。观察模式仍禁止发送与继续。Claude 的暂停确认规则保持不变，须等中断完成后才能继续。

Claude 运行中发送指令通过 CLI stream-json 的 `priority: now` 输入插入当前会话；不启动第二个进程，也不要求等待整轮自然结束。暂停会优先发送 interrupt 并取消等待队列，避免插队指令在暂停后又开始运行。只有与本次中断意图、轮次匹配的 `Interrupted` 或特定 `[ede_diagnostic]` 回执才归为正常中断；其他执行错误仍会提醒。进程由本监控启动并持有才可控制；原窗口占用时只读关注。

Codex 开启自动推进的任务在额度耗尽后进入“等待额度刷新”，不会反复发送继续指令。程序持久保存受限窗口的刷新时间；短周期和长周期均受限时等待较晚的时间。到点重新读取官方额度，只有 `ordinaryUsageAllowed=true` 且限制已解除，才自动恢复原来的 `usageLimited` 目标并继续一次。不修改目标内容、用量或预算；已完成、目标暂停、预算受限、无控制权或待审批的任务不自动恢复。接口未知或未返回刷新时间时会明确显示并定期重新查询，不靠时间推断恢复。手动“暂停任务”、关闭自动推进或移出会取消自动恢复，重启后仍尊重这些选择。

主界面围绕当前任务与下一步操作展示。后台返回失败或结果不确定时弹窗提醒；消息发送失败且输入框为空时恢复原草稿，已有新草稿不会被覆盖。点按钮表示已提交，仍需等最终状态确认。送达不确定时不自动重发。

Claude 的“自动推进”由本监控定时器实现：默认关闭，手动开启后先等待一小时，随后只对本监控持有、实时空闲、没有待审批或执行错误的会话发送一次继续指令。周期、发送预留和结果写入本地控制库；暂停或关闭后不再发送，送达不确定时关闭自动推进，不能盲目重试。任务完成后应关闭此开关。Codex 保留自己的 goal 和调度检查。

启动时只加载旧操作历史，不重弹过去的失败。新操作失败仍会提醒，历史记录继续保存在本机。

## 吉光片羽

从案头左栏底部或系统托盘打开。「吉光片羽」用于记录灵感和思考，随记可编辑、归档和恢复。「待办」用于记录要做的事，可以标记完成或恢复为待处理。编辑会自动保存，也可以手动点击「保存」。

笔记和待办保存在桌面实例数据目录的 `lanxi-notebook.sqlite3`，源码运行时为项目根目录，EXE 运行时为其所在目录。

## 登录启动与验收

`scripts/install-startup.ps1` 优先将 `release/Lanxi.exe` 注册为当前用户登录入口，其次兼容旧桌面 EXE，最后使用源码方式启动。已有计划任务可按运行文档更新。

Qt smoke 使用虚构会话核验界面按钮和显示。真实模型收发、工具审批往返、系统通知实际展示、重新登录和故障恢复需要在本机另行验收，不能从打包成功或 smoke 通过推断。
