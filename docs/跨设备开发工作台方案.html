跨设备开发工作台

在公司用 VS Code 写到一半，回家打开 PyCharm，在终端输入平时的 codex，接着同一个项目和同一段对话工作。需要本地算力的步骤交给家里电脑，iPhone 随时查看进度。

方案日期 2026 年 11 月 18 日　·　基线提交 d42de0c　·　状态：待实施与真机验收

项目要求

三台 Windows 电脑使用同一套任务小站。一次安装、配对并登记项目后，后台负责交接。日常开发路径仍是打开 IDE、编辑、运行命令，用户无需另开工作台或点击同步。

代码和会话一起到达

三端保留代码副本。已保存到磁盘的未提交修改、暂存状态、允许同步的新文件和最近可恢复的 Codex 轮次必须相互对应；绝对路径按设备映射。

人拥有最高优先级

任一设备用 VS Code 或 PyCharm 打开项目，任务小站释放该项目的自动控制。最后一个 IDE 关闭、人工 CLI 释放后，后台按原策略接回。

算力和大文件按需使用

普通开发就近执行，GPU 任务或受本机性能限制的可迁移步骤自动调度到家里。大对象默认一份持久主副本，工作缓存按需生成，重要数据另存冷备。

夜间可独立推进

项目按长期、短期或探索性管理。夜间在项目沙箱和预算内自动处理符合规则的操作审批，iPhone 可暂停、看结果和处理例外。

总体架构

三台电脑分别连接项目原有的 Git 远程。家里节点保存已确认的交接版本，并协调写入权。桌面、CLI 和手机都以同一个项目标识关联任务，磁盘盘符只保存在各设备的映射里。

层次接口与持久状态
用户入口PyCharm / VS Code 终端运行 Codex CLI。Qt 托盘与 Web 调用同一后台；iPhone 通过经鉴权的 HTTPS 入口查看项目或发起已有控制操作。
本机设备代理复用现有 worker 生命周期，采集文件变更、IDE 实例、CLI 活动和资源能力。本机 SQLite 持久化发送队列、最近确认版本与未完成作业，重启后对账。
中心协调服务在家里运行 FastAPI 和独立的 SQLite。保存项目、设备、快照清单、项目控制权、会话写入租约、作业编号和额度记录。设备凭证和浏览器登录分别鉴权。
数据与计算Git 管代码版本，Syncthing 搬运已封存的交接材料，Gitea LFS 存大对象。家庭 worker 按项目环境和输入版本运行作业，回传日志、退出码和输出对象。

协调服务用递增的控制权版本拒绝已过期设备的写入，提交同一作业编号只产生一次执行。操作结果未知时先向执行节点核对。旧设备重新上线后，先保存它的独立变更，再决定能否合并。

开发与运行环境

开发与构建

以 Windows 11、PowerShell、Python 3.10+、Node.js 22+ 为开发基线。仓库的 Web 验证记录使用 Python 3.14 与 Node.js 26.13.1。前端按 package-lock 安装，后端依赖按用途锁定。

仓库当前声明 PySide6 6.12.0、FastAPI 0.163.1、Uvicorn 0.54.0、React 19、TypeScript 5、Vite 6，Windows EXE 沿用 PyInstaller 打包。发布时记录实测 CLI 版本及兼容清单。

日常设备

公司机为基础显示显卡，型号待探测。笔记本为 RTX 3050，显存容量和运行时可用量以实测为准。家里电脑同时承担开发、协调与重计算，首次启动探测显卡、驱动、运行环境、内存、磁盘和可用带宽。

iPhone 使用 Safari 访问同一 Web 工作台，可添加到主屏幕。首次配置完成设备配对、项目目录映射、各端 CLI 登录和家庭节点登录启动。

在平时开启 VPN 的条件下联调

分别探测模型服务、Git 远程和家里中心节点的可达性。优先复用已有获准网络。若 VPN 占用了默认路由、DNS 或手机的 VPN 通道，验证可共存的路由，或采用经鉴权的 HTTPS 网关访问家庭服务。iPhone 的日常路径设计为保持现有 VPN 开启，覆盖 Wi-Fi、蜂窝和网络切换后的重连。

各机维护自己的解释器、虚拟环境与驱动。工作区内引用本机绝对路径的配置按设备映射；锁定依赖和可复现的项目设置随代码版本管理。

无感换机与数据一致性

  1. 后台准备。设备代理按项目监听已保存文件，以 Git 基线、暂存版本、工作树版本和允许同步的新文件生成快照。补齐尚未推到远程的必要 Git 对象。缓存、密钥、虚拟环境和未经登记的原始大数据按排除规则处理。
  2. 确认一组可恢复数据。CLI 完成一轮且持久记录稳定时，记录项目 ID、线程 ID、轮次、工作目录映射、代码版本及所需对象哈希。中心核对对象齐备后原子发布版本；工作区随后产生的修改进入下一版。
  3. 另一台提前准备。本机后台预取最近项目，在独立目录校验，再安全更新空闲工作区。IDE 已打开或本地出现新修改时先保留本地状态。两个版本从同一基线安全合并；同一处发生冲突时保存双方内容并提示。
  4. 终端照常启动。首次登记时为受管项目配置终端启动适配。在对应目录输入 codex 时按项目选择已验证的线程 ID，交给真实 CLI 恢复；显式子命令、主动新建会话和未登记目录沿用 CLI 原语义。对话在目标机映射后的工作目录执行。
  5. 中断后恢复。网络离线时记录本地修改。中心不可达时可查看已确认进度，自动写入权等恢复连接后再核对。对执行结果不明的命令先查状态；已经运行的外部终端在原机到达安全点后才转移该线程。

首项技术验证　在两台 Windows 的不同盘符、两个 IDE 的真实终端中，输入同一条日常启动命令，核对原线程 ID、历史轮次、实际工作目录和新回复。编辑器尚未落盘的缓冲区、运行中进程和 GPU 显存不能当作可恢复快照。

大文件与低磁盘

仓库存指针，大文件按需下载工作副本。单主副本所在设备离线时，界面显示可用缓存或等待来源；重要对象按策略在另一台设备保留第二份。调度先从在线且空间充足的节点中选址，预留整次上传所需容量。初始候选阈值为剩余低于 10% 停止分配、低于 5% 进入只读，真机测试后调整。

冷文件迁移按复制、目标哈希校验、事务切换索引、清理旧副本的顺序执行。上传期间固定目标，迁移失败继续从旧副本读取。每个阶段可在重启后重试。

人工优先与夜间审批

控制权按项目判断。 任一设备用 VS Code 或 PyCharm 打开登记项目，立即阻止任务小站发起新的自动操作，释放该项目的控制连接。后台可以继续采集设备状态、封存快照和完成用户从前台发起的计算。远端快照先放入暂存区，避免改写用户正打开的工作树。

事件任务小站的行为
IDE 打开项目通过两个 IDE 的项目打开、关闭事件和心跳报告规范化路径，覆盖多窗口和 VS Code 多根工作区。先撤销自动推进与自动审批权，取消未发送的后台操作；执行中的步骤到可安全停止的位置再释放。
关闭 IDE 或崩溃最后一个相关窗口关闭后核对其余设备、外部 CLI、待处理工具调用和实际进程。确认人工已释放后自动连接，按项目原有设置恢复。心跳中断或失联先核对，避免误抢控制权。
进入睡眠时段按用户本地时区和设定时段生效。项目已启用夜间托管、写入权有效且预算充足时，允许在项目沙箱内读写、构建和测试，并对策略覆盖的当前工具审批自动答复。
超出沙箱或预算项目根目录以外写入、提权、未授权联网、读取凭据及发布操作进入等待。按规范化真实路径检查链接与重解析点，子进程继承沙箱。平台无法落实对应隔离时保留待审批。次日显示动作、依据、结果与文件变更。

已有审批绑定原连接及请求 ID。新版本只审批仍有效的请求，记录项目、设备、时间和规则。用户在夜间打开 IDE、点击暂停或撤回托管，后台立即停止发出新的审批及调度动作。一次夜间工具审批不会替用户决定新的产品需求或扩大任务范围。

硬件感知与家庭计算

交互留在当前 IDE 和 CLI。需要 CUDA 的训练、推理、图像处理等项目命令，以及受本机资源持续限制的可迁移作业，由家里 worker 执行。Codex 通过在线模型服务生成回复；家庭显卡承担项目实际启动的本地计算程序。

判断时机决策与动作
运行前从项目已登记的运行配置、解释器、框架探测和历史峰值取得资源需求。需要 GPU 时优先选家里可用且环境匹配的 GPU。公司机只承担已验证能跑的任务；RTX 3050 按实际显存与用户策略作为可行的本地执行端。
运行中按作业采样进度、耗时、显存压力、可用内存、换页、CPU 和磁盘等待。资源不足错误可立即触发重新选址，持续低吞吐需结合历史基线及多个采样窗口判断。高 GPU 利用率本身可能是正常工作。
决定切换比较本机剩余时间与传输、排队和家庭执行时间。中心核对家里在线、资源余量、驱动、依赖和输入版本。可断点任务保存检查点再恢复，允许重复执行的步骤从头重跑，有外部副作用或无安全边界的步骤保留现场。
结果回到终端用项目运行入口或 CLI 可调用的作业适配器提交，保持原命令的退出码、日志和取消语义。输入使用固定快照；输出按哈希回传，在原项目版本仍匹配时落盘。用户在前台发起的作业沿用前台所有权。

验证范围　先接入一个项目真实使用的 GPU 命令和一个 CPU 命令。记录源设备、路由原因、队列等待、传输耗时、执行耗时和结果一致性。家庭 GPU 型号、显存、带宽及切换阈值以设备实测为准。

任务类型与 Codex 用量

项目登记时选择默认类型，单个任务可以覆盖。以下是建议默认策略，预算数值和睡眠时间由设置保存。

类型调度与结束条件
长期项目保留跨天目标和检查点，按每日预算推进。交还给人工时保留待办，夜间仅执行已定义范围内的工作。
短期任务设完成条件、单任务预算和截止时间。完成或预算用尽即停止自动推进，记录交付物。
探索性任务在独立工作区隔离尝试，限制轮次、耗时与预算，保留结论与实验记录，由用户决定是否将成果合入主项目。

台账同时展示账号官方短、长额度窗口及刷新时间，以及按项目和线程累计的可观测 token、轮次与运行时长。每条记录按线程、轮次和事件标识去重。官方未提供的指标标为未知；项目统计用于预算控制，账号共享额度按服务端返回值展示。

到达项目预算后暂停该项目；账号额度耗尽时所有相关任务等待官方刷新。恢复前重新核对人工占用、任务目标、预算和沙箱策略。手机可查看“哪个项目用了多少、为何暂停、何时重查”。

开发计划与验收

按可独立验证的里程碑交付。优先解决真实终端续接和控制权交接，再增加后台计算与夜间自动化。每阶段保存测试环境、输入、实测结果、失败记录与回滚点。

里程碑交付物与通过条件
一 · 真实 CLI 续接双机、不同盘符和两种 IDE。A 留下已暂存、未暂存及新增文件，B 在终端输入 codex 后继续原线程。核对文件与暂存标记、线程 ID、新一轮实际目录；统计额外手动操作数，正常路径目标为 0。
二 · 统一后台与控制权Qt、Web 和托盘共用本机后台，接入 IDE 项目生命周期。用三机、多窗口、外部 CLI、IDE 崩溃、断网和重启验证人工优先、自动接回及冲突保全；检查没有重复指令或陈旧审批。
三 · 手机与大文件在现有 VPN 开启时，用真实 iPhone Safari 从 Wi-Fi、蜂窝查看进度、暂停和处理待审批。实测家庭 LFS 预取、校验失败和中断恢复，验证缺少必需对象时不会误报就绪。
四 · 硬件自动调度公司机发起 GPU 作业，核对家庭设备执行、终端结果与文件校验。笔记本测试本地资源充足、显存不足、家里忙碌和中途掉线。比较本地运行与远程端到端耗时，检查同一作业只交付一次。
五 · 分类、额度与夜间验证三类任务的结束条件、额度去重、超额暂停和到点重查。夜间沙箱内构建通过，越界操作留待审批，用户半夜打开 IDE 后自动审批立即停发，次日可核对全部动作。
六 · 存储与发布验证容量阈值、冷迁移、双副本和唯一来源离线。统一安装器复用已有工具，支持客户端或家庭中心角色、登录启动、升级与回滚。用原有 Python 回归、Qt smoke 和 Web 测试覆盖已有功能。

首轮联调要记录的现场数据包括三机实际 CLI 和终端版本、家庭 GPU 与网络带宽、典型大文件体积、公司机可同步项目、VPN 路由、常用 GPU 命令和睡眠时段。用这些数据确定兼容矩阵、性能预算及排期。
